# Performance Test Fixes v1.3.2

## Issue: Validation Framework Regression in CI Environment
- **Description**: v1.3.1 fixes worked locally but failed in CI environment with foreign key constraint violations and "innings not found" errors
- **Root Cause**: Local mutex variables in validation framework defeated mutex protection, causing race conditions in CI
- **Fix Applied**: Replaced local mutex with global mutex and enhanced unique ID generation for better test isolation

## Issue: Foreign Key Constraint Violations
- **Description**: `balls_over_id_fkey` constraint violations when creating balls due to invalid over IDs
- **Root Cause**: Over IDs were not being validated after creation, allowing empty or invalid IDs to be used
- **Fix Applied**: Added validation to ensure over ID is not empty after creation before proceeding

## Issue: Test Data Interference Between Workers
- **Description**: Multiple test workers interfering with each other's data creation in CI environment
- **Root Cause**: Insufficient unique ID generation and local mutex variables not providing proper isolation
- **Fix Applied**: Enhanced unique ID generation with additional entropy and global mutex protection

## Technical Changes:
### Mutex Protection Fix:
- **Before**: `var testDataMutex sync.Mutex` (local variable, ineffective)
- **After**: `var globalTestDataMutex sync.Mutex` (global variable, effective)
- **Result**: Proper mutex protection across all test workers

### Foreign Key Validation:
- **Before**: No validation of over ID after creation
- **After**: Validate over ID is not empty before proceeding
- **Result**: Prevents foreign key constraint violations

### Enhanced Test Isolation:
- **Before**: `uniqueID := fmt.Sprintf("%d-%d-%d-%s", ...)`
- **After**: `uniqueID := fmt.Sprintf("%d-%d-%d-%d-%s", ...)` (added userID length)
- **Result**: Better unique ID generation preventing data interference
